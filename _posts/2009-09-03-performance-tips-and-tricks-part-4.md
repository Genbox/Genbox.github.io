## Boxing and unboxing

[Boxing](https://learn.microsoft.com/en-us/dotnet/csharp/programming-guide/types/boxing-and-unboxing) is the process of encapsulating a
value type into a reference type. Unboxing is the reverse process. They both take some time and
might happen several times in your application without your knowledge. Here is some example code on
boxing/unboxing:

```csharp
int number = 60;
object obj = (object)number; //Boxing
int newNumber = (int)obj; //Unboxing
```

Since `int` is a primitive and thus a value type, it gets
boxed and stored on the heap.
This makes our lives easy, but it also comes at a [performance
penalty](https://learn.microsoft.com/en-us/previous-versions/dotnet/articles/ms973852(v=msdn.10)?redirectedfrom=MSDN).

You can easily identify boxing and unboxing operations by their IL code names:

```text
.method private hidebysig static void Main(string[] args) cil managed
{
    .entrypoint
    .maxstack 1
    .locals init (
        [0] int32 number,
        [1] object obj,
        [2] int32 newNumber)
    L_0000: nop
    L_0001: ldc.i4.s 60
    L_0003: stloc.0
    L_0004: ldloc.0
    L_0005: box int32
    L_000a: stloc.1
    L_000b: ldloc.1
    L_000c: unbox.any int32
    L_0011: stloc.2
    L_0012: ret
}
```

Boxing is called **box**; the unboxing and value-copy operation shown here is **unbox.any** in IL code. You can use
[Reflector](https://www.red-gate.com/products/reflector/) to have a look at the IL code generated by
your application.

Boxing is very expensive performance wise. Try to avoid encapsulating value types into reference
types. Try to find other ways of doing the same, you can use
[generics](https://learn.microsoft.com/en-us/previous-versions/ms379564(v=vs.80)?redirectedfrom=MSDN) as an example.

## Exception handling

Exceptions are great for reporting problems. Many logging systems catch exceptions thrown and log
them to a file. The problem is that exceptions are [expensive to use and
catch](https://www.codeproject.com/KB/exception/ExceptionPerformance.aspx). In high performance
applications, keep throwing and catching exceptions off the normal path through performance critical code. All data should be
sanitized, checked and exceptions should be thrown before the data enters the performance critical
part of the code.

A few things you should think about when using exceptions:

- Do not throw exceptions inside loops
- Do not throw exceptions inside performance critical code
- Do throw exceptions in helpers, managers and data layers and other run-once and use-multiple times
  code.

The last item can be a bit of a gray area since you can use helpers, managers and data layers inside
performance critical code. I trust you to figure that part out yourself.

## String operations

Strings can be your best friend or worst nightmare. They are easy to use and easy to manipulate.
What could be wrong with using strings?

They are
[immutable](https://web.archive.org/web/20100324070215/http://codebetter.com:80/blogs/patricksmacchia/archive/2008/01/13/immutable-types-understand-them-and-use-them.aspx).
Memory allocations and thus garbage collections can become a problem. C# does a really [great
job](https://web.archive.org/web/20100311232603/http://en.csharp-online.net:80/CSharp_String_Theory%E2%80%94String_intern_pool) of optimizing
strings in such a way that minimum memory allocations take place. But even then there is still
quite an overhead of using strings. Operations that change string contents produce another string;
reading or comparing an existing string can reuse its storage. The new string takes up some space (2 bytes for each
character) and the whole memory copying operation also takes some time. Let’s take a look at some
string concatenations:

### Normal string

```csharp
string example = "";
for (int i = 0; i <= 9; i++)
{
    example += i;
}

Console.WriteLine(example);
```

Using this code you will get the string “0123456789”. Problem with this code is that you allocate 11
strings. Yes, that is right, 11 strings:

- initial allocation = 1
- appending = 10
- final result = 1

The allocation, the representation and writing the string to the console in C# takes up nearly 4 kb.
The string operation itself takes up a couple of 100 bytes.

### StringBuilder object

A better solution compared to normal strings is to use the StringBuilder object. It
contains a mutable (changeable) array.

```csharp
StringBuilder example = new StringBuilder();

for (int i = 0; i <= 9; i++)
{
    example.Append(i);
}

Console.WriteLine(example);
```

The StringBuilder object allocates a lot less, but it still has an overhead. It is an object, it
contains a resizable array, it has a lot of functionality. Allocating a StringBuilder object
often can [actually be slower](https://www.chinhdo.com/20070224/stringbuilder-is-not-always-faster/)
than normal strings.

### `char` arrays

`char` arrays can be [even
faster](https://learn.microsoft.com/en-us/archive/blogs/cisg/performance-analysis-reveals-char-array-is-better-than-stringbuilder).
They are mutable arrays with managed-object overhead.

```csharp
char[] example = new char[10];

for (int i = 0; i <= 9; i++)
{
    example[i] = (char)(i + 48);
}

Console.WriteLine(example);
```

A `char` array can be faster than a StringBuilder object for simple operations (measure your case), but it
also has some disadvantages:

- You have to know the maximum size of the string (`char` array is fixed size)
- Can only be used in simple manipulation scenarios.
